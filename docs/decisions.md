# Decisions log

Baseline for every design doc and all code. It resolves gaps and contradictions in the [spec](../stakeholder-notepad-spec.md), cited as §n.

- **Precedence:** this file > spec > other files in `docs/`. If a doc or code disagrees with this file, this file wins. Change a decision here first, then update the docs.
- **Status:** `Decided` means an engineering decision. `Owner` means the default stays in force until the product owner answers the linked question.
- Cite decisions as `DEC-nn` in docs, code comments and PRs. Never renumber. Mark a replaced entry "Superseded by DEC-nn".

Second, the build-logic plugin `doro.test-apk-keep-rules` (`TestApkKeepRulesPlugin`, applied in `app/build.gradle.kts`, DEC-03). For a minified `qa` or `benchmark` variant that has an androidTest component, which AGP creates only for the `-PtestBuildType` build type (`TestApkKeepRules.appliesTo`, unit-tested to be false for `release`), it registers the cacheable task `generate<Variant>TestApkKeepRules` and adds its output to the variant's `proguardFiles` through the Variant API (`variant.proguardFiles.add`). The task runs R8 TraceReferences `--keep-rules` on class files in a separate JVM with a 1 GB heap, with AGP's own R8 from the `com.android.tools.build:builder` artifact of the applied AGP version (a detached, non-transitive configuration; R8 9.5.29 today). The source is the test APK's `ScopedArtifact.CLASSES` (scope ALL); the target is the app's `CLASSES` (scope ALL), what R8 reads; the library is the compileSdk boot classpath plus its optional `android.test.base`, `android.test.mock` and `android.test.runner` jars, which the device provides to the runner through `uses-library`. Dex inputs cannot be used: TraceReferences 9.5.29 ignores dex given as `--target`. The task writes `app/build/intermediates/doro_test_apk_keep_rules/<variant>/test-apk-keep-rules.pro`, whose first line starts with the marker `# doro.test-apk-keep-rules`, in three sections, and a fourth for an obfuscating variant. Section 1 is TraceReferences' plain `-keep` for every app class, field and method the test APK references. Section 2 is `-keep class X { *; }` for every app type that a test-APK class or `invokedynamic` lambda extends or implements, and for each of its app supertypes (`ClassHeader` reads the superclass, the interfaces and the return types of the `CONSTANT_InvokeDynamic` entries; only app interfaces count). A narrower rule is unsound: R8 full mode does not treat a kept class as instantiated, so it may remove or replace inherited members that a test-only subclass reaches only through platform types, such as `Iterator.next()` of `AbstractIterator`. Section 3 is `-keep class S { *; }` for every app type the test APK provides `META-INF/services` implementations of, which keeps R8 from rewriting the app's `ServiceLoader.load` of it into its own providers (`runTest` needs kotlinx-coroutines-test's providers). Section 4, only for a variant that R8 obfuscates (`qa`: none of the variant's own R8 configuration files, its DSL `proguardFiles` outside the build directory, holds `-dontobfuscate`; `proguard-benchmark.pro` does, so the `benchmark` rules hold sections 1 to 3 alone, byte for byte as before; the task fails on an `-include` in those files, which this check cannot follow, and a build-logic test reads the real `proguard-rules.pro` and `proguard-benchmark.pro`), is `-keep,allowshrinking,allowoptimization,allowaccessmodification class * extends C` (`implements` for an interface) for every non-public app type C that sections 1 to 3 keep with a plain `-keep` (`ClassHeader.isPublic`, `TestApkKeepRules.packageRules`): every app subtype of C, at any depth, keeps its name and therefore its package, and R8 may still remove, optimize, merge or publicize it. The task fails, in every variant, on an option line of sections 1 to 3 that is neither such a plain type `-keep` nor `-keeppackagenames` (`TestApkKeepRules.unreadableOptions`), so no kept type is skipped silently. Why: on the `qa` rules of b709295 the `qa` app crashed at start in `InitializationProvider.onCreate` with `IllegalAccessError` (`release-smoke`, 2026-11-22, build/t22-smoke, where no test ran), with or without the test APK. R8 had renamed `kotlin.collections.CollectionsKt__MutableCollectionsJVMKt` to `h10` in the root package, where it extended the package-private multifile part `CollectionsKt__IterablesKt`, which section 1 keeps because TraceReferences resolves the test APK's call of the facade `CollectionsKt.collectionSizeOrDefault` to the part that defines it; the unused parts `CollectionsKt__IteratorsJVMKt` and `CollectionsKt__IteratorsKt`, which stood between the two, were gone from the mapping. Observed with R8 9.5.29 in the `qa` dex and a minimal reproduction, not read from R8's sources: a kept class keeps its access flags while its kept members are made public, and in full mode with `-allowaccessmodification` R8 moves classes it renames into the root package.
